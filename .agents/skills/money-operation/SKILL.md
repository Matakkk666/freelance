# Денежная операция

Применяй к любому коду, который создаёт, меняет или показывает деньги. Правила M1–M13 —
в [AGENTS.md](../../../AGENTS.md#правила-для-денег-обязательные), модель ledger —
в [docs/architecture.md §3](../../../docs/architecture.md#3-ledger-внутренний-кошелёк).

## 1. Спроектируй проводки до кода

Выпиши таблицу: какие счета, какие суммы и знаки, сумма в каждой валюте = 0 (M3).
Если нужен новый системный счёт, добавь его в architecture.md §3 и в seed-миграцию.
Вставь таблицу в описание PR.

## 2. Ключ идемпотентности (M5)

Ключ детерминирован и выводится из бизнес-события, а не генерируется случайно:
`deposit:<provider>:<external_id>`, `order:<order_id>:capture`, `subscription:<id>:<period_start>`,
`referral:<reward_id>`, для корректировок из админки — `Idempotency-Key` из запроса.
Повтор с теми же параметрами возвращает первый результат, с другими — ошибку.

## 3. Транзакции (M2, M6)

- Проводки и связанные записи (заказ, подписка, вознаграждение, аудит) — в одной транзакции БД.
- Проводки создаются только через сервис ledger. Прямой `UPDATE accounts` запрещён.
- Внешний вызов (партнёр, процессинг) — только между транзакциями, никогда внутри.
- Неизвестный исход внешнего вызова → `processing` + сверка, а не возврат.

## 4. Суммы (M1)

- `Decimal` из строки (`Decimal("10.5")`), никогда из float. Квантование — money-хелпером ledger.
- В API — строки. Во frontend никакой арифметики, только отображение.
- Цены, комиссии и проценты берутся из БД (M11), а не из констант.

## 5. Причина и инициатор (M9, M10)

Корректировки и реферальные начисления заполняют `reason` и `created_by`. Действие из админки
пишет `audit_log` в той же транзакции.

## 6. Обязательные тесты (M13)

- [ ] успешный сценарий: балансы всех затронутых счетов после операции;
- [ ] сумма проводок = 0 (и попытка несбалансированной операции падает);
- [ ] повтор с тем же ключом не меняет балансы, с другими параметрами — ошибка;
- [ ] недостаточно средств → понятная ошибка, ничего не записано;
- [ ] конкуренция: параллельные операции (`asyncio.gather`, отдельные соединения через фикстуру
  `engine`) не уводят баланс в минус и не дублируют начисления;
- [ ] для админки — запись аудита есть, и её нет, если операция откатилась;
- [ ] для внешних вызовов — сценарии успех, отказ, таймаут.
