## Текст

### ТЗ заказчика

MVP финтех-сервиса с личным кабинетом пользователя:
- регистрация и авторизация;
- внутренний баланс / кошелёк пользователя;
- история операций и транзакций;
- криптокарты через API поставщика;
- eSIM через API;
- подарочные карты и цифровые товары через API;
- внешний виджет;
- VPN-сервис;
- подписка с тремя тарифами: Стандарт, Plus, Premium; стоимость, комиссии
  и доступные функции настраиваются;
- обязательная реферальная программа: уникальная ссылка или код, учёт приглашённых,
  начисление и история вознаграждений, условия настраиваются в админке;
- простой пользовательский интерфейс;
- базовая админ-панель.

Почти все продукты предоставляют партнёры через API. Наша задача — единый backend
и интерфейс, который их объединяет. Подписки и рефералка входят в базовую архитектуру.
Для кошелька и крипты берём готовую инфраструктуру и API, свой блокчейн не делаем.
Цель — рабочий MVP без лишней сложности, который можно запустить на реальных пользователях.

### Что уже решено

- Кошелёк: внутренний ledger по двойной записи в нашей БД. Реальные деньги хранятся
  у криптопроцессинга или кастодиального провайдера (выберем позже). Пользователь
  видит внутренний баланс.
- Пока считаем, что баланс в одной валюте (USDT), но валюта — это поле счёта,
  чтобы потом можно было добавить другие.
- Покупка у партнёра: резерв средств → запрос к партнёру → списание при успехе,
  снятие резерва при отказе. При таймауте ставим статус «в обработке» и сверяемся
  с партнёром, а не делаем автоматический возврат.
- Каждый внешний сервис (криптокарты, eSIM, подарочные карты, VPN, процессинг, KYC)
  подключается через свой адаптер. Пока нет ключей и документации, работаем на моках.
  API партнёров не выдумываем: документация будет лежать в docs/partners/.
- Тарифы, комиссии, функции тарифов и условия рефералки хранятся в БД
  и меняются из админки, а не в коде.
- Реферальные начисления и ручные корректировки баланса проходят только проводками
  ledger с указанием причины.
- Этап 1: авторизация, кошелёк с пополнением через криптопроцессинг, история,
  подписки, рефералка, админка, eSIM и подарочные карты.
  Этап 2: VPN, виджет, криптокарты (зависят от поставщика и KYC).

### Что пока неизвестно (заказчик ещё не ответил)

Поставщики, способы пополнения, кто проводит KYC, юрисдикция, платформа (веб или
Telegram Mini App), какой нужен виджет, дизайн. Выбирай решения, которые оставляют
эти варианты открытыми, и записывай их в docs/decisions.md.

### Стек (если нет веских возражений)

- Backend: Python 3.12+, FastAPI, SQLAlchemy 2 (async), Alembic, Pydantic v2,
  PostgreSQL (не SQLite).
- Frontend: React + TypeScript + Vite, mobile-first, чтобы позже его можно было открыть
  как Telegram Mini App. Админка — раздел того же фронтенда, права проверяются на backend.
- Проверки: ruff, mypy --strict, pytest (тесты БД на настоящем Postgres), eslint, tsc,
  vitest. Всё запускается одной командой `make check`.
- CI на GitHub Actions запускает `make check` на каждый PR.
